> **Updated:** 2026-08-17 (#128 — **`--strict` ne sort plus 0 sur ce qu'il n'a pas mesuré** ([[ADR-0033]]) : le gate CI sortait **0** sur des projets dont une partie du code n'avait jamais été mesurée — démontré par Security sur binaires release, pas en théorie (`--max-kwh 0.0009 --strict` contre 0,0013 kWh réel ; gonfler **un** fichier au-delà de la garde de taille le sort de la somme gatée, l'énergie retombe à 0,0006 et l'outil sort 0). Aucun bug : **deux décisions individuellement correctes** qui se composent mal — `AlertThresholds::evaluate` applique délibérément « une métrique absente ne franchit jamais un seuil » ([[ADR-0010]], [[ADR-0017]] §2) et `gated_exit_code` n'observait que `has_breach()`, d'où le **même exit 0** pour « rien n'a dépassé » et « rien de ce que j'ai su mesurer n'a dépassé ». Le rapport, lui, était **déjà honnête** : c'est le code de sortie seul qui perdait l'information, sur le seul canal qu'une CI lit. Option retenue en GATE 1.5 : **un code dédié, `4`**, jamais une réutilisation de `3` — rabattre sur `3` aurait satisfait **la lettre** du critère (via le message) en perdant l'information sur ce canal, c'est-à-dire en reproduisant le défaut du ticket un étage plus bas ; écartées aussi le flag `--fail-on-unmeasurable` seul (laisse le défaut ouvert par défaut, ne protège que qui lit la doc) et le statu quo documenté. AD-1 : `3` inchangé et **l'emporte** sur `4` ; `4` ssi `strict` ∧ seuil configuré ∧ couverture ≠ `Complete` ∧ aucun dépassement ; hors `--strict` l'exit reste 0 (AC3) ; un seul message imprimé, celui du code gagnant (Q3, arbitrage humain) — **changement de contrat assumé**, un dépôt à gros fichier généré voit sa CI changer de couleur, ce que `--strict` promettait déjà. AD-2 : deux faits, deux porteurs — `ThresholdReport` dit *ce qui a dépassé*, `GateCoverage` dit *sur quoi j'ai pu décider* ; les fusionner forcerait `evaluate` à connaître les échecs de lecture, donc **`alert_thresholds.rs` sort de la tranche à diff nul**, vérifié aux quatre passes ; porté par `GatedOutput<T>` dont la raison d'être documentée est « ce dont la CLI a besoin pour décider du code de sortie », et `new` prend la couverture en **troisième argument positionnel obligatoire** — rupture assumée avec l'idiome builder du dépôt, parce qu'un builder rend le fait *oubliable* et qu'un site d'appel qui l'oublie retombe **silencieusement** sur `Complete`, soit sur le mensonge même qu'on corrige ; effet de bord consigné : **34 mutants `unviable`**, la conception a supprimé la classe de bug au lieu de tester autour. AD-3 : **quatre gardes de même forme** — *l'adaptateur laisse tomber un fichier et le domaine ne l'apprend jamais* — trouvées l'une après l'autre et **par sondage adverse, jamais en lisant le diff** : `MAX_MEASURABLE_SOURCE_BYTES` (1 Mio, domaine, fermée d'emblée), `MAX_FILE_SIZE` (10 Mio, adaptateur, fermée retry 1 via `dropped_files`), `MAX_WALK_DEPTH` (128, fermée retry 2), `hidden(true)` — **toujours ouverte, #147** ; la *forme* est la leçon : tout abandon au niveau adaptateur doit atteindre le domaine. AD-4 : la troncature en profondeur n'émet **ni `Ok` ni `Err`**, aucun mécanisme indexé par chemin ne pouvait la voir, et personne ne peut dire combien de fichiers vivent dans un sous-arbre jamais parcouru — les compter serait la fabrication qu'[[ADR-0010]] interdit ; d'où `Partial { unmeasurable_files: usize, unexplored_subtree: bool }`, un **compte** pour ce qui a pu être nommé et un fait **non quantifié** pour ce qui ne pouvait pas l'être, rendus en **deux clauses séparées jamais fusionnées**, dans la porte ouverte par `Absent` ([[ADR-0032]] AD-5 : un adaptateur qui ne peut pas lire un signal propage l'absence, il ne fabrique jamais une valeur plausible) ; alimenté par deux prédicats **exacts** (entrée de répertoire à `entry.depth() == MAX_WALK_DEPTH`, et `Err` extérieur dont le chemin résout vers un répertoire), alignement vérifié **exact** par Security — `128` est précisément la première profondeur à laquelle un fichier cesse d'être livré, **sans profondeur-trou**. AD-5 : [[ADR-0010]] demande au *rapport* de dire ce qu'il n'a pas mesuré ; #128 montre que **le rapport ne suffit pas quand le consommateur est une CI**, qui ne lit que le code de sortie — corollaire appliqué **dans le ticket** : le retry 2 avait créé un `Partial` invisible sur JSON/HTML (un tableau de bord voyait un projet sain), replié dans la tranche plutôt que ticketé, parce que c'était **notre propre dette**. AD-6 : une trouvaille **retirée sur preuves** — ré-appliquer le filtre d'extension dans la branche `Err` a produit **4 survivants de mutation, zéro kill**, puis six sondages sur système de fichiers réel ont montré que tout `WithPath` atteignable sur cette pile nomme un **répertoire**, jamais un fichier (`ignore` parse les gitignore avec indulgence, APFS refuse l'UTF-8 invalide, la construction de forme fichier vit dans le marcheur parallèle jamais construit) ; Security a nommé une seconde raison dirimante — le filtre ne pouvait que transformer un `Partial` en `Complete`, soit **un exit 4 en exit 0**, échangeant du *fail-closed* contre une sortie plus silencieuse ; le **revert est consigné comme correct**, et toute réintroduction exige une **preuve d'atteignabilité, pas une dérogation de gate de mutation**. Section obligatoire **« Ce que `--strict` ne couvre pas »**, dans la discipline d'[[ADR-0010]] appliquée à la porte : **#147 (HIGH)** — un chemin commençant par `.` sort **entièrement** du gate, sans trace sur aucune surface, démontré par une charge de 1 600 fonctions réellement dépassante s'échappant par un simple renommage (`heavy/` → cx 3 241, exit 3 ; `.heavy/` → cx 1, **exit 0 silencieux**), représentable en git et survivant à un clone frais, préexistant (#83), correctif = **décision d'architecture** (compter les entrées cachées écartées dans la couverture, ou rendre `hidden` configurable *et* rapporté) et **surtout pas** un `hidden(false)` sec qui ingérerait `.git/`/`.venv/` ; **#145** — `exclude` de `.codeimpact.json` rétrécit l'ensemble mesuré sans trace exploitable par machine (`default_excluded_count` ne compte que le sous-ensemble *par défaut*), ce qui **défait la remédiation documentée d'[[ADR-0006]]** (les flags surclassent les **seuils**, jamais `exclude`), cause de fond : deux niveaux de confiance — opérateur vs dépôt analysé — effondrés sur un unique `FileFilter` ; **#146** — un nom de fichier hostile laissant un attribut SGR actif peut masquer visuellement l'avertissement, l'hexagone ne pouvant atteindre `sanitize_console_text` sans inverser la règle de dépendance ; et le cas **`ignore::Error` sans chemin**, sondé et trouvé **structurellement inatteignable** sur le marcheur séquentiel (`from_walkdir` attache `WithPath` en position externe ; les deux constructions sans chemin exigent `follow_links(true)`, fixé à `false`, ou le marcheur parallèle, jamais construit) — consigné **clos par analyse**, pas comme de la dette, pour qu'une relecture future ne le rouvre pas par prudence. [[ADR-0017]] **amendé** (§4 : trois codes de sortie → quatre), [[ADR-0006]] **amendé** (§ *Frontière de confiance* : sa remédiation était trompeuse telle qu'écrite), [[alert-thresholds]] **corrigé** (le nœud faisant autorité contredisait le code — trouvaille `major` de Dev-B) et [[architecture-overview]] mis à jour.
